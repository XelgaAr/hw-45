# Проверка проекта

## Автоматические сценарии

`npm run test:core` — 12 выполненных независимых тестов логики. Всего в `tests/` предусмотрено 15 unit-тестов. В `e2e/` — 3 сценариев, каждый запускается на desktop и mobile Chromium, то есть 6 браузерных выполнений при полном запуске.

```bash
npm install
npm run check
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты используют production-сборку, query-параметры и/или localStorage согласно функциям проекта. Не запускайте второй preview на порту 4173 одновременно. HTML-отчёт после E2E можно открыть командой `npx playwright show-report`.

Проверки, зависящие от npm, подготовлены, но не выполнены в исходной среде. Их успешность нужно подтвердить локально или в GitHub Actions; см. `CHECK_REPORT.md`.

## Ручная проверка

1. Добавить задачу с названием из пробелов: появляется ошибка, диалог не закрывается.
2. Создать задачу, изменить описание, категорию и приоритет, отметить выполненной.
3. Проверить поиск, все фильтры, сортировку, счётчики и сброс фильтров.
4. Перезагрузить страницу: задача и её статус сохранены, фильтры возвращаются к начальным.
5. Удалить задачу с подтверждением; отдельно удалить все выполненные.
6. Открыть `?view=legacy`, повторить создание и перезагрузку; вернуться к основной версии и убедиться в независимости данных.

Дополнительно проверьте ширины 320, 390, 768 и 1440 пикселей, перемещение по элементам клавишей Tab, закрытие диалогов клавишей Escape, Console и Network в DevTools. Откройте опубликованный URL непосредственно в новой вкладке, затем перезагрузите его: ресурсы должны загружаться без 404.

## Что не заменяет E2E

Успешные unit-тесты доказывают только проверенные свойства логики. Синтаксический разбор не устанавливает библиотеки и не проверяет реальный React-rendering. Mock API в тесте подтверждает обработку заданного ответа, но не доступность живого внешнего сервиса.
